## 成果验收：  
本架构依赖环境、路径进行了延迟绑定，可以轻松通过 **.env** 配置文件和 **requirements.txt** 文件进行部署。  
同时，在 **Scripts** 文件夹下写了 **open_client.bat** ，**start_server_test.bat**， **start_server_pure.bat** ，**start_server.bat** 4个文件，在配置好环境后，点击即可打开客户端，配置并运行服务器，test会为服务器导入一些基础数据以供测试；pure会清空服务器现有数据，纯净开始；最后一个则直接保持现有的服务器开始。  
也有 **录制视频** 以供老师进行成果验收。  
关于要求的二进制文件，由于均由python编写，源码分发更符合 Python 的灵活性、跨平台特性和社区文化，因此仅提供了批处理文件。
### 部署&测试：

1.  在.env文件中配置PostgreSQL数据库！
2.  运行 [scrips/start_server_test.bat](./scrips/start_server_test.bat)，将清空并重建数据库，导入默认测试数据以提供测试。
3.  运行 [scrips/open_client.bat](./scrips/open_client.bat), 打开客户端， 注册账号并登录。同一局域网下不同端可同时使用。
4.  如果客户端部分logo等图片无法显示，请使用pycharm打开Client文件夹，配置里面的虚拟环境并运行application.py。

## 架构总结与评估：

架构总体采用了分层架构和服务器-客户端混合模式（参考[CS版组合架构视图](./docs/CS版组合架构视图（如果graffle文件打不开看这个）.png)）.各层均经过独立开发和测试。架构分层严格，不会产生跨层的桥接。  
内部层仅user_server有状态，会为顶层提供相应的user_view并对其权限、活跃性进行异步管理。客户端在与服务器同一局域网下均可多端多用户同时正常使用。

### 评估：

#### 优点：
* 使用多层架构和服务器-客户端模式，将底层功能与展示分离开来。开发时可以相对并行地处理模式的所有层。
* 高易用性。架构在内部维护了用户模型，外部层调用API即可跟踪user_view的状态，无需单独维护状态。用户模型能记住用户的偏好，使得软件易用性高。
* 高可测试性。实现了了双通道日志系统，可以同时分别记录系统内部和外部的日志，使得开发调试更容易。各层单独测试，并提供了一系列测试文件，以及批处理文件进行测试。
* 高防护性。user_server跟踪用户状态已检查用户安全性。密码复杂度强制要求，内部采用哈希等加密算法进一步增强防护性。
* 高可修改性。架构分层明晰，低耦合高内聚，并向上向下兼容（新版架构系统层完成兼容旧版桌面应用程序。新版架构系统层对下一次作业同样完全兼容）。用户可通过桌面应用程序，客户端以及将来的web浏览器同时操作本系统。
* 高可用性。系统内部对异常进行监测，阻止或掩盖失效。
* 高可部署性。适应虚拟环境和延迟绑定，部署环境配置方便。支持跨平台部署。

#### 缺点：
* user_view采用观察者模式的思想，如果未能及时对不活跃用户的内存进行释放，会导致服务器内存压力过大。
* 查询工作由无状态机map_server维护，对于一定数量的地图不存在任何问题。但将来地图数量到达大数据的规模，则需要重构以适配数据分析查询。
* 数据库中change表会存在很多空白的部分，将产生额外资源消耗，影响数据库查询效率。
* 无论矢量还是栅格，文件系统将地图储存的格式均为tiff，路径储存在数据库中。容易被窃取。若地图涉及敏感文件，未来可通过数据库加密和储存格式管道加密等方法提升防护性。
